CASE STUDY 02 · BANKING ANALYTICS

Banking Customer Intelligence & Retention

Connecting churn-risk modelling to prioritised outreach and retention case management.

Open live application ↗View source repository ↗

THE QUESTION

Which customers may need retention attention, how should a bank prioritise limited outreach capacity, and how can follow-up be tracked?

An end-to-end customer analytics workflow spanning data quality, churn modelling, probability calibration, independent evaluation, risk queues, campaign planning and case follow-up.

01 / CONTEXT

Why this problem matters.

Customer churn is not only a classification task. A bank needs portfolio visibility, a ranked worklist, an understanding of relationship-manager capacity and a way to track what happens after outreach. The project frames these needs through Nyanja Commercial Bank, a fictional Malawi-focused banking scenario, with monetary values expressed in MWK.

02 / APPROACH

How the work is structured.

01

Data preparation

A reproducible cohort-generation and validation workflow checks schema, missingness, duplicates, category consistency and implausible values before feature preparation.

02

Model development

A majority-class baseline, Logistic Regression and Random Forest are compared. Validation data is used for candidate and threshold decisions; the independent final test partition is held back for evaluation.

03

Calibration and governance

A sigmoid calibrator is fitted using five-fold cross-validation within the training partition. Evaluation includes discrimination, classification trade-offs, probability quality and subgroup diagnostics.

04

Operational workflow

Full-population scores support portfolio monitoring and prioritisation. The app adds configurable outreach queues, relationship-manager allocation, campaign CSV exports and a retention case register.

WHAT THE ANALYSIS SHOWS

The repository intentionally loads current performance metrics from saved model artefacts rather than hard-coding a possibly stale score table in the README. Logistic Regression is retained as the initial recall-oriented operating candidate, while model selection remains conditional on intervention cost, outreach capacity and false-positive/false-negative trade-offs.

04 / PRACTICAL RELEVANCE

How the output can be used.

A retention team can review portfolio exposure, filter customer segments, adjust contact capacity, distribute a ranked worklist across relationship managers, export an execution list and track case status and next follow-up. Model Governance makes threshold and calibration trade-offs visible alongside the scores.

05 / TECHNOLOGY

Tools and implementation.

SCOPE & LIMITATIONS

Interpreting the results.

The project demonstrates how churn-risk modelling can inform customer retention strategies. Results are based on a generated customer cohort and should not be interpreted as measured banking performance.
