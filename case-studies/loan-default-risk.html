CASE STUDY 04 · CREDIT RISK ANALYTICS

Loan Default Risk Prediction

Building a leakage-aware default-risk workflow and making threshold trade-offs explicit.

Open live application ↗View source repository ↗

THE QUESTION

How can borrower and loan characteristics support a more structured assessment of default risk without treating a model score as an automatic lending decision?

A reproducible credit-risk workflow covering data validation, feature engineering, Logistic Regression, Random Forest and XGBoost, probability evaluation, threshold analysis, interpretation and risk segmentation.

01 / CONTEXT

Why this problem matters.

A fictional Malawi-focused commercial bank wants to understand how borrower affordability, repayment history and financial characteristics relate to default. The project uses a generated cohort of 20,007 loan applications and frames the work as an analytical case study, not a live credit decision system.

02 / APPROACH

How the work is structured.

01

Clean the records

The workflow documents missing values, outliers, inconsistent categories, duplicate rows and invalid ages. Outliers are capped, exact duplicates removed, invalid ages treated as missing and unknown branches retained explicitly.

02

Engineer meaningful features

Examples include monthly repayment ratio, savings-to-income ratio, previous-default flag, late-payment frequency, loan-burden category and credit-risk category.

03

Train leakage-aware pipelines

A stratified 75/25 train/test split is used. Numeric imputation and scaling plus categorical imputation and one-hot encoding are fitted on training data only. Logistic Regression, Random Forest and XGBoost are compared.

04

Evaluate decision trade-offs

Precision, recall, F1 and ROC-AUC are considered together. Threshold analysis explores the cost of catching more potential defaulters versus creating more false positives for manual review.

WHAT THE ANALYSIS SHOWS

Random Forest achieved ROC-AUC 0.776, accuracy 0.752, precision 0.371 and recall 0.629 at the reported default classification setting. Logistic Regression had the highest default-class recall among the compared models at 0.672. At a 0.40 Random Forest threshold, recall rose to 0.782 while precision was 0.294; 2,297 of 5,002 held-out borrowers were flagged high-risk.

04 / PRACTICAL RELEVANCE

How the output can be used.

A credit-risk analyst can inspect borrower segments, compare model behaviour, examine threshold scenarios and review which factors consistently contribute to risk estimates. The result is a structured review aid and a basis for discussion—not an automated approval or rejection rule.

05 / TECHNOLOGY

Tools and implementation.

Python · Pandas · NumPy · Scikit-learn · XGBoost · Jupyter Notebook

06 / INTERPRETATION & LIMITATIONS

What this project does not claim.

The generated target and cohort are designed for methodological demonstration, not evidence of real borrower default behaviour. The 0.40 threshold is a starting point for discussion; a real bank must validate false-positive and false-negative costs, affordability policy, review capacity and fairness on authorised representative data. Model outputs must not make lending decisions by themselves.
